## 1. Критично перед публичным запуском (1–2 недели)

### 1.1 Секреты и окружение
- [ ] Убрать `.env` из репозитория, проверить `git log` — текущий `.env`
      с реальными ключами уже засвечен, **ключи Mistral/Azure пересоздать**.
- [ ] На Render задать: `DATABASE_URL` (Neon), `GEMINI_API_KEY`, `AZURE_*`,
      `FISH_API_KEY`, `ADMIN_PASSWORD` (не дефолтный!), `SESSION_SECRET` (длинный).
- [ ] Разные БД/ключи для dev / staging / prod.

### 1.2 Безопасность
- [ ] Пароли: сейчас минимум 4 символа — поднять до 8 + rate-limit на логин
      (`express-rate-limit`: 10 попыток / 15 мин / IP), иначе брутфорс.
- [ ] Куки сессии: добавить `secure: true`, разделить секреты по ролям;
      сейчас подпись HMAC — ок для MVP, дальше — сессии в Redis/БД с отзывом.
- [ ] Пароли учителей никогда не показывать3259 в открытом виде (сейчас так и есть —
      только сброс через создателя). Сохранить это правило навсегда.
- [ ] Валидация и лимиты: `topicId` — число, тексты — trim + max-length,
      `helmet`, CORS по белому списку, `express-mongo-sanitize`-аналог не нужен (pg),
      но параметризованные запросы — везде (уже так).
- [ ] Защита `POST /api/voice/tts` от абуза: требовать студенческую сессию,
      лимит символов/минут на пользователя в сутки, иначе любой сольёт Fish-квоту.

### 1.3 Данные и БД
- [ ] Миграции вместо `CREATE TABLE IF NOT EXISTS` в коде
      (`node-pg-migrate` или `knex`): версии, откаты, seed создателя.
- [ ] Бэкапы Neon (автоснапшоты включить), `pg_dump` перед каждым деплоем схемы.
- [ ] Индексы: `progress(topic_id, student_key)`, `topics(teacher_id)`.
- [ ] Связать `progress.student_key` с реальным `students.id`
      (сейчас строковый ключ `anon-xxx` / логин — мигрировать на FK).

### 1.4 Надёжность ИИ
- [ ] Mistral: таймауты (сейчас их нет — зависший fetch висит вечно),
      бюджет токенов на ученика/день, graceful-degrade («ИИ перегружен, попробуйте позже»).
- [ ] Валидация JSON от модели схемой (zod): сейчас `JSON.parse` упадёт на мусоре —
      добавить repair-ретрай (1 повтор с «верни только JSON»).
- [ ] Логи всех AI-вызовов (модель, latency, токены) — считать себестоимость.

## 2. Продукт: чтобы это был «полноценный проект» (3–6 недель)

### 2.1 Аккаунты и роли
- [ ] Роли в одной таблице `users(role: student|teacher|admin)` вместо трёх таблиц.
- [ ] Профиль ученика: имя, аватар, класс, язык по умолчанию.
- [ ] Восстановление пароля (email/код), смена пароля в профиле.
- [ ] Привязка ученика к учителю/классу (код класса): учитель видит только своих.

### 2.2 Обучение
- [ ] Программа курса: темы → модули → порядок, прогресс-бар по курсу, а не по теме.
- [ ] Уровни и геймификация: XP, streak, бейджи — сейчас streak считается, но не показывается красиво.
- [ ] Типы заданий: выбор варианта, ввод числа, шаги решения; проверка на бэке, а не только LLM.
- [ ] История уроков ученика («мои занятия»), продолжение с того же места.
- [ ] Экспорт прогресса (CSV) для учителя + печатный отчёт для родителей.

### 2.3 Голос
- [ ] Выбрать и зафиксировать 1 женский RU-голос и 1 KK-голос из каталога Fish
      (сейчас дефолт «Училка» `e3ca0b02…` — послушать 3–5 кандидатов на одном тексте и выбрать).
- [ ] Стриминг TTS (chunked audio), предзагрузка озвучки следующего задания.
- [ ] Переключатель «голос вкл/выкл» в профиле (сейчас только кнопка в чате).
- [ ] Субтитры под озвучкой для слабослышащих.

### 2.4 Казахский язык — довести до равного с русским

- [ ] Проверка качества `kk-KZ` STT на школьной лексике; при плохом — Web Speech API

- [ ] Тесты носителем: теория/задания Mistral на казахском часто слабее — отдельный
      системный промпт уже есть, нужен ревью-режим учителя («исправить теорию»).

### 2.5 UX/дизайн
